# Структура репозитория BrVIdge

Документ описывает структуру репозитория. Раздел 0 фиксирует то, что
создано фактически; раздел 2 — **проектируемую** структуру на последующие
фазы. Каталоги `tests/` и часть `crates/` появятся по мере реализации.

---

## 0. Фактически создано (24.11.2026)

```text
BrVIdge/
├── Cargo.toml                  # workspace, resolver 3, edition 2024
├── Cargo.lock                  # создан cargo, внешних зависимостей нет
├── rust-toolchain.toml         # 1.99.1, x86_64-pc-windows-msvc
├── .cargo/config.toml          # псевдоним cargo xtask
├── .gitignore
├── crates/
│   ├── brv_common/             # ошибки, LeReader, fnv1a64, hex_dump
│   ├── brv_pe/                 # PE32+/COFF, импорты, RVA, синтетический образ
│   ├── brv_loader/             # prepare(), Resolver, отчёт о missing imports
│   ├── brv_hle/                # реестр HLE-модулей, HostPolicy, census
│   ├── brv_gpu/                # D3D12-прототип (единственный crate с unsafe)
│   ├── brv_shader/             # декодер подмножества RDNA2 + HLSL
│   ├── brv_dxc/                # компиляция HLSL → DXIL через dxc.exe из SDK
│   ├── brv_runtime/            # синтетический title и HLE-вызовы в процессе
│   ├── brv_config/             # TOML-подмножество, профили Series X/S
│   ├── brv_log/                # файловый логгер с уровнями
│   ├── brv_diag/               # отчёт о среде и asset-policy
│   ├── brv_exec/               # PE32+ в память, релоки, потоки (второй crate с unsafe)
│   ├── brv_shader_cache/       # контент-адресуемый кэш шейдеров
│   └── brv_formats/            # тайлинг, BC1, явный «не реализовано» для BCPack
├── apps/brv/                   # CLI: inspect, imports, census, prepare, gpu, shader, dxil, run, selftest
└── xtask/                      # build, test, all, sample
```

Остальные каталоги из раздела 2 — **планируемые**, а не существующие.
Ни один игровой файл не включён в репозиторий.

## 1. Общий принцип

- Один Cargo workspace, каждый модуль — отдельный crate с чётким контрактом.
- Имена crates начинаются с `brv_`, исполняемые приложения лежат в `apps/`.
- Идентификаторы в коде — английские; комментарии, логи и документация — русские.
- Игровые данные, ключи, дампы и кэши **не попадают** в git.
- Любой новый модуль добавляется только с техническим обоснованием
  (см. таблицу необходимости в [ARCHITECTURE.md](ARCHITECTURE.md)).

## 3. Назначение ключевых каталогов

| Каталог | Что хранит | Что НЕ хранит |
|---|---|---|
| `crates/brv_pe` | разбор PE32+, таблиц импортов/экспортов, релоков | исполняемые файлы игр |
| `crates/brv_loader` | отображение в адресное пространство процесса, TLS, обработка исключений | контакты с DRM |
| `crates/brv_hle` | реализации системных вызовов, виртуальные диски, offline-сервисы | сетевую авторизацию Xbox Live |
| `crates/brv_gpu` | объекты консольного D3D12.X, интерпретатор записей списков команд | проприетарные заголовки/библиотеки консоли |
| `crates/brv_shader` | декодер RDNA2, IR, транслятор, кэш DXIL | шейдеры из игр |
| `crates/brv_formats` | общедоступные/наблюдаемые форматы данных | расшифровку XVC/MSIXVC |
| `tests/fixtures` | только синтетические материалы | файлы GTA VI и любой другой игры |
| `data/` | пользовательские пути, кэш, сейвы, логи | файлы, являющиеся частью репозитория |

## 4. Правила тестов

1. `cargo test --workspace` проходит без игровых данных и без GPU.
2. GPU-тесты пропускаются с явным сообщением `SKIPPED`, если нет подходящего
   адаптера или DXC; пропуск не считается «пройденным тестом».
3. Тесты на реальных данных — опциональные, включаются переменными окружения
   и путями к файлам пользователя. В репозитории таких файлов нет.
4. Каждый найденный системный вызов должен быть зафиксирован в тесте
   или в отчёте о неподдерживаемых API.

---

## 5. Воспроизводимость

- Версия Rust фиксируется в `rust-toolchain.toml`.
- Версии зависимостей — в `Cargo.lock`.
- Сборка и тесты — через `cargo xtask` (одна точка входа).
- Любой сгенерированный код (таблицы инструкций, swizzle-таблицы) должен
  иметь генератор в `xtask/` или `scripts/` и описание источника лицензии.
