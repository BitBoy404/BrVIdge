# Дорожная карта BrVIdge

Версия: 1.0 (24 ноября 2026 года).
Статус: **Phase 7 выполняется (частично)**. Phase 1–6 завершены. Phase 8–10 не начинались.

---

## 0. Правила перехода между этапами

1. Этап считается завершённым только при наличии **проверяемого результата**:
   зелёные тесты, успешная сборка и стабильно воспроизводимый артефакт.
2. Результат фиксируется в отчёте с командой запуска и выводом.
3. Запрещено переходить к следующему крупному этапу, если предыдущий
   не имеет такого результата.
4. Любая «заглушка» обязана явно сообщать, что функциональность не реализована.
5. После каждого этапа обновляются: ROADMAP, RISKS, FEASIBILITY, README
   (таблица статусов).

## Phase 4 — Prototype

**Цель:** доказать работоспособность ключевых идей на собственных тестовых
программах, без файлов игры.

| Прототип | Что проверяет | Критерий |
|---|---|---|
| Синтетический PE32+ «title» | загрузчик, импорты, TLS, вызов shim | программа печатает результат и завершается |
| Минимальный парсер PE/импортов | анализ исполняемого файла | корректный список import/dll на фикстуре |
| D3D12 triangle | бэкенд, PSO, swapchain | окно с треугольником, цвет проверен readback |
| Декодер RDNA2 (подмножество) | таблицы инструкций из MIT-источника | 100% совпадение имён/длин на собственном наборе |
| RDNA2 → HLSL → DXIL (1 программа) | транслятор | DXIL проходит валидацию, GPU-тест совпадает с CPU-эталоном |
| Валидация DXIL | tools | валидатор принимает результат |
| Воспроизводимая сборка xtask | инфраструктура | `cargo xtask build` и `cargo xtask test` на чистой машине |

**Команды проверки:** `cargo xtask build`, `cargo xtask test`,
`cargo run -p brv -- inspect <fixture>`, `cargo run -p brv -- shader <fixture>`.

**Ворота Phase 4:** все прототипы зелёные; ни один тест не требует игровых
данных; GPU-тесты либо проходят, либо явно помечены `SKIPPED`.

### Фактический результат (24.11.2026, первый запуск кода)

Выполнено:

| Прототип | Статус | Подтверждение |
|---|---|---|
| Воспроизводимая сборка xtask | готово | `cargo xtask all`: сборка и 36 тестов зелёные; `cargo clippy --workspace --all-targets -- -D warnings` без предупреждений |
| Синтетический PE32+-образ | готово | `cargo xtask sample <путь>` записывает 1536 байт полностью собственного образа |

| Подготовка копии образа | готово | `brv prepare`: снимает DLL-флаг и FORCE_INTEGRITY, обнуляет entry point, checksum, каталоги импортов и TLS; `.text` не меняется |
| Resolver импортов | готово | таблица правил HLE/Host/TitleDll/Stub и честный отчёт о неподдерживаемых импортах |
| Реестр HLE и HostPolicy | готово | `brv census` классифицирует импорты: HLE 1, HOST 0, НЕ РЕАЛИЗОВАНО 1 |

| Валидация DXIL | готово | DXC проверяет DXIL при компиляции; тест `generated_hlsl_compiles_to_valid_dxil` |
| Запуск синтетического title в процессе | готово | `brv run --synthetic`: 3 HLE-вызова, код выхода 0, все выделения освобождены |

**Ворота Phase 4 пройдены:** все прототипы зелёные, 36 тестов, ни один тест
не требует файлов игры. Ограничение, зафиксированное явно: DXIL-конвейер

цель Phase 7. Реальная загрузка PE и системные API переносятся в Phase 5/6.

## Phase 5 — Core Runtime

**Цель:** единый процесс с конфигурацией, логированием, диагностикой
и главным циклом.

| Задача | Критерий |
|---|---|
| Cargo workspace, crates, xtask | `cargo build --workspace` |
| brv_config / brv_log / brv_diag | конфиг загружается, логи пишутся в `data/`, отчёт о среде |
| brv_runtime: жизненный цикл, runner | запуск собственного `sample_title` |
| Asset-policy проверка | коммит с игровым файлом отвергается |
| Профили Series X / Series S | конфигурация выбирается и отображается в диагностике |

**Ворота Phase 5:** синтетическая программа запускается через `brv run`,
возвращает ожидаемый код выхода, лог содержит все запрошенные API.

### Фактический результат (24.11.2026)

| Задача | Статус | Подтверждение |
|---|---|---|
| Cargo workspace, crates, xtask | готово | `cargo xtask all`: 51 тест, clippy без предупреждений |

## Phase 6 — CPU Backend

**Цель:** не эмулировать x86, а обеспечить корректное выполнение кода на хосте.

| Задача | Критерий |
|---|---|
| PE32+: секции, релоки, импорты, delay-load, TLS, SEH | тесты на синтетических PE |
| Resolver: HLE → игра → Windows → stub | все варианты покрыты тестами |
| Crash reporter: module+RVA, stack unwind | воспроизводимый искусственный сбой даёт ожидаемый отчёт |
| Управление потоками: affinity, приоритеты | тест с несколькими потоками, нет дедлоков |
| Таблица покрытия API | каждый вызов зафиксирован в log/report |

**Ворота Phase 6:** `brv run <synthetic title>` завершается корректно,
`report.json` содержит ожидаемые вызовы, неподдерживаемые API перечислены.

### Фактический результат (24.11.2026)

| Задача | Статус | Подтверждение |
|---|---|---|
| PE32+: секции и релоки | готово | `brv_exec::map_image`: VirtualAlloc, копирование секций, `DIR64`/`HIGHLOW`, VirtualProtect; тест проверяет patched-значение по RVA 0x1200 |
| Нативный запуск кода | готово | `brv native`: `mov eax,imm32; ret` из синтетического PE выполняется процессором, код выхода совпадает (42, 17) |
| Resolver HLE/Host/Title/Stub | готово | 5 тестов `brv_loader` на все четыре варианта |
| Crash reporter | частично | `capture_crash`: module+RVA и стек через `std::backtrace`; реальный VEH-перехват сбоя не реализован |
| Управление потоками | готово | `CreateThread`, `SetThreadPriority`, `SetThreadAffinityMask`, ожидание и код выхода; 2 потока без дедлока |
| Таблица покрытия API | готово | `data/report.json`: `api_calls=3`, `api_log` с тремя вызовами, `unsupported_api="нет"` |

**Ворота Phase 6 пройдены в рамках прототипа:** `brv run` возвращает 0,
JSON-отчёт содержит ожидаемые вызовы и список неподдерживаемых API.
TLS-колбэки, delay-load и реальный SEH для настоящих игр переносятся в Phase 8.

## Phase 7 — GPU Backend

**Цель:** перевести консольный GPU-код и команды в понятный D3D12.

| Задача | Критерий |
|---|---|
| D3D12 device, queues, swapchain, PresentX-эмуляция | кадр отображается, readback корректен |
| D3D12.X objects + console command list interpreter | собственная запись команд интерпретируется без ошибок |
| Pipeline manager, root signature, descriptor tables | PSO создаётся, ресурсы привязываются |
| RDNA2 → DXIL, EXEC/wave64/waterfall, atomics | дифференциальные GPU-тесты |
| Shader cache (content-addressed) | повторный запуск не компилирует заново |
| Тайлинг/BCPack (только с открытыми таблицами) | синтетические эталоны |

**Ворота Phase 7:** тестовая сцена на собственных шейдерах рисует ожидаемую
картину; тесты wave64-on-wave32 и 64-bit atomics проходят; DXC-память
ограничена Job Object.

### Фактический результат (25.11.2026, промежуточный)

| Компонент | Статус | Подтверждение |
|---|---|---|
| D3D12 device, queues, SwapChain | готово | `brv present`: скрытое окно, `CreateSwapChainForHwnd` с command queue, 2 кадра через Present |
| Xbox GPU Command Lists | частично | `brv_gpu::console_list`: интерпретатор 9 типов записей, 4 теста. Формат — собственный, не реконструкция D3D12.X |
| Pipeline manager, root signature, descriptors | готово | `brv_gpu::manager`: кэш по content hash, allocator с повторным использованием, 5 тестов |
| RDNA2 → DXIL | частично | декодер расширен до 11 инструкций; `brv_dxc` компилирует расширенную программу в DXIL `cs_6_0` и валидирует DXC |
| Shader cache | готово | `brv_shader_cache`: ключ зависит от версии и содержимого, atomic write+rename, 4 теста |
| Тайлинг/BCPack | частично | `brv_formats`: 256B XOR-тайлинг (собственная модель) и полный BC1 — 6 тестов; BCPack явно возвращает «не реализовано» |

**Ворота Phase 7 пока НЕ пройдены:** не сделаны wave64-on-wave32,
64-битные atomics, ограничение DXC-памяти через Job Object, полный формат
D3D12.X и BCPack. Переход к Phase 8 запрещён до подтверждения этих пунктов.

## Phase 8 — System Compatibility

**Цель:** подменить недостающие сервисы консоли.

| Задача | Критерий |
|---|---|
| Память: guest VA, UMA, 4 GiB windows, бюджет | тесты shared CPU/GPU без копий |
| Файловая система: `GAME:`, `G:`, `D:`, overlay | записи не меняют каталог title |
| XGameRuntime offline, XUser, saves, пакеты | собственный тест проходит офлайн |
| Аудио: PCM + доступные кодеки | тестовый тон воспроизводится |
| Ввод: геймпад, клавиатура | тест реагирует на ввод |

**Ворота Phase 8:** синтетический title читает файл, пишет сейв, играет тон
и реагирует на ввод; сетевые вызовы блокируются и логируются.

## Phase 9 — Integration

**Цель:** соединить подсистемы в один запускаемый стек.

| Задача | Критерий |
|---|---|
| Единый `brv run` | все подсистемы инициализируются в нужном порядке |
| Сквозной синтетический сценарий | загрузка → API → кадр → звук → ввод → выход |
| Регрессионный прогон | `cargo xtask test` зелёный |
| Профилирование | отчёт по CPU/GPU/памяти на целевой машине |

**Ворота Phase 9:** сквозной тест стабилен 10 запусков подряд; утечек и
недетерминизма нет.

**Важно:** переход к тестам на GTA VI возможен только при наличии
**легально полученных** файлов и отдельного решения. Без них Phase 9 —
предел проверяемой разработки.
