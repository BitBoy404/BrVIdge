# Зависимости и лицензии BrVIdge

Документ фиксирует **предварительный** стек и правила выбора зависимостей.
Фактический `Cargo.lock` появится в Phase 4. Ни один сторонний исходный код
не копируется в репозиторий до проверки лицензии.

---

## 1. Выбор лицензии проекта

**Рекомендация: GPL-3.0-or-later.**

Обоснование:

- ближайший по задаче публичный проект — VIctory — распространяется под
  GPL-3.0-or-later; архитектурные решения можно изучать и обсуждать;
- выбор GPL-3 позволяет использовать MIT/BSD/Apache-2.0-with-LLVM-exception,
  LGPL-2.1+, LGPL-3.0 и GPL-3.0 компоненты;
- **но** BrVIdge не сможет напрямую копировать код XCL и AnyPS5:
  оба — GPL-2.0-only. Такое копирование потребует изменения лицензии BrVIdge
  на GPL-2.0-only и отказу от кода под GPL-3.

Практическое правило: **изучаем архитектуру, реализуем самостоятельно**.
Если позже появится необходимость заимствовать конкретный файл, его лицензия
проверяется отдельно и вносится в таблицу ниже.

## 2. Матрица совместимости лицензий

| Источник | Лицензия | Можно использовать в GPL-3.0-or-later? | Комментарий |
|---|---|---|---|
| VIctory | GPL-3.0-or-later | да (при сохранении лицензии) | только при фактическом копировании; мы-plan clean-room |
| XCL | GPL-2.0-only | **нет** (без отдельного разрешения) | совместим только с GPL-2.0-only проектом |
| AnyPS5 | GPL-2.0-only | **нет** | рекомпилятор RDNA → SPIR-V |
| Xenia | BSD-2-Clause | да | нужно сохранить copyright-уведомление |
| WinDurango | LGPL-3.0 | да | в XCL используется только как ссылка |
| AMD Machine-Readable ISA | MIT | да | таблицы инструкций, генерация декодера |
| Mesa addrlib | MIT | да | swizzle-таблицы GFX10 |
| AMD GPURT | MIT | да | формат BVH-узлов (public-источник) |
| LLVM / DXC | Apache-2.0 WITH LLVM-exception / NCSA | да | формат DXIL, валидатор, тестовые вектора |
| FFmpeg | LGPL-2.1+ | да | XMA-декодер (если потребуется) |
| libHttpClient | MIT | да | контракт XTaskQueue/XAsync |
| DXC (`dxcompiler.dll`, `dxil.dll`) | NCSA / Microsoft | да, **не распространяется** | берётся из Windows SDK пользователя |
| Windows SDK / D3D12 / XGameRuntime | системные компоненты | да | не включаются в репозиторий |
| Игровые файлы, ключи, заголовки SDK | проприетарные | **нет** | не используются |

Отдельный риск: XCL получил от автора VIctory персональное разрешение
использовать часть кода BCPack под GPL-2.0-only. BrVIdge **не должен**
предполагать наличие такого разрешения для себя.

## 3.0 Фактические зависимости (24.11.2026)

- `brv_common`, `brv_pe`, `brv_loader`, `brv_hle`, `brv_shader`, `brv_dxc`,
  `brv_runtime`, `brv_config`, `brv_log`, `brv_diag`, `brv_shader_cache`,
  `brv_formats`, `apps/brv`, `xtask` —
  **только стандартная библиотека**,
  внешних crates нет.
- `brv_gpu` — единственный crate с внешней зависимостью:
  `windows = 0.62.2` с фичами `Win32_Foundation`,
  `Win32_Graphics_Direct3D`, `Win32_Graphics_Direct3D12`,
  `Win32_Graphics_Direct3D_Fxc`, `Win32_Graphics_Dxgi_Common`.
  Лицензия `MIT OR Apache-2.0`, совместима с GPL-3.0-or-later.
  Через `windows-core` добавляет 14 транзитивных пакетов; все версии
  зафиксированы в `Cargo.lock`.
- `brv_shader` использует числовые факты (коды операций и битовые поля)
  из AMD Machine-Readable GPU ISA Specification (MIT), с атрибуцией
  в заголовке исходного файла. Код XCL не копировался.
- `brv_dxc` вызывается как внешний процесс `dxc.exe` из Windows SDK
  (`BRV_DXC` или `C:\Program Files (x86)\Windows Kits\10\bin\*\x64\dxc.exe`).
  Бинарники DXC/DXIL не распространяются с BrVIdge. `brv_gpu` для тестового
  треугольника использует `D3DCompile` из системной `d3dcompiler_47.dll`.

`unsafe` разрешён только в `brv_gpu` и `brv_exec` (второй использует
`windows` с фичами `Win32_Foundation`, `Win32_Security`,
`Win32_System_Memory`, `Win32_System_Threading`); во всех остальных crates
он запрещён.

## 3. Предполагаемый стек

### Обязательный минимум

| Компонент | Версия/источник | Обоснование |
|---|---|---|
| Rust | зафиксировать в `rust-toolchain.toml` (1.88+ / edition 2024) | основной язык; нужен для безопасной работы с парсерами и IR |
| Cargo | в составе Rust | workspace, тесты, воспроизводимая сборка |
| Windows 10/11 SDK | 10.0.22000+ | заголовки D3D12/DXGI, DXC |
| DXC | 1.8+ (`dxcompiler.dll`, `dxil.dll`) | компиляция HLSL → DXIL |
| D3D12 Agility SDK | опционально | SM 6.6+ на Windows 10 (inbox D3D12Core.dll может быть SM 6.5) |
| DirectX Shader Compiler (`dxc`) runtime | из SDK пользователя | не распространяется с BrVIdge |
| CMake | только при появлении C++-компонента | пока не требуется |

### Предполагаемые Rust-зависимости (минимум)

| Crate | Назначение | Лицензия |
|---|---|---|
| `anyhow`, `thiserror` | ошибки и контекст | MIT / MIT OR Apache-2.0 |
| `clap` | CLI | MIT OR Apache-2.0 |
| `serde`, `toml` | конфигурация | MIT OR Apache-2.0 / MIT OR Apache-2.0 |
| `tracing`, `tracing-subscriber` | логирование | MIT |
| `object` | разбор PE/COFF | MIT OR Apache-2.0 |
| `windows-sys` / `windows` | вызовы Win32/D3D12 | MIT OR Apache-2.0 |
| `blake3` | контент-адресуемый кэш | CC0-1.0 OR Apache-2.0 |
| `miniz_oxide` | zlib/zlib-ng decoder | MIT OR Zlib OR Apache-2.0 |
| `memchr`, `walkdir`, `tempfile` | утилиты | MIT OR Unlicense / MIT OR Apache-2.0 |

Это **не** финальный список: зависимости добавляются только вместе с модулем,
который их реально использует.

### Намеренно исключаемые зависимости

- Полноценные эмуляторы CPU / JIT-библиотеки x86 — не нужны.
- Тяжёлые графические движки (wgpu, bevy и т.п.) — не нужны, нужен прямой D3D12.
- Любые библиотеки для снятия DRM, расшифровки XVC или обхода защиты — запрещены.
- Vulkan как основной бэкенд — не нужен на Windows; опция рассматривается
  только при появлении обоснованной необходимости.

## 4. Сторонний код, который может появиться позже

| Компонент | Источник | Условие включения |
|---|---|---|
| Таблицы инструкций RDNA2 | AMD Machine-Readable ISA (MIT) | генератор в `xtask/`, provenance в заголовке файла |
| Swizzle-таблицы GFX10 | Mesa addrlib (MIT) | только таблицы/факты, не код XCL |
| Формат BVH-узлов | AMD GPURT (MIT) / публичные спецификации | только после синтетических тестов |
| Формат DXIL | LLVM/DXC (Apache-2.0 WITH LLVM-exception / NCSA) | только открытая спецификация и собственные тесты |

Любой файл, содержащий логику стороннего происхождения, обязан иметь
в заголовке комментарий на русском: источник, лицензию, дату и характер изменений.

---

## 5. Политика активов

- В репозитории нет и не будет файлов игр, кэшей шейдеров из игр, дампов
  текста/текстур, ключей и заголовков закрытых SDK.
- `xtask asset-check` (когда будет реализован) проверяет, что в коммите
  нет файлов с расширениями игровых ресурсов и больших бинарников.
- Тесты на реальных данных включаются только через переменные окружения
  с путями к файлам пользователя и пропускаются без них.
