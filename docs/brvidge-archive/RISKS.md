# Технические риски и неизвестные факторы BrVIdge

Статус: предварительный анализ, Phase 1. Оценки вероятности и влияния
субъективны и должны пересматриваться после каждого этапа.

Обозначения: **В** — вероятность, **У** — ущерб (низкий/средний/высокий/критический).

|---|---|---|---|---|

## 3. Архитектурные и технические риски

| ID | Риск | В | У | Митигация |
|---|---|---|---|---|
| T1 | Формат консольных списков команд D3D12.X и внутреннее устройство объектов неизвестны и меняются между версиями | высокая | критический | Поэтапная реконструкция по собственным фикстурам; изоляция в `brv_gpu`, журналирование вызовов. |
| T2 | Трансляция RDNA2 → DXIL: EXEC-маски, wave64, DPP/SDWA, 64-битные atomics, waterfall-циклы | высокая | критический | SSA IR, структуризация, дифференциальные тесты на собственных шейдерах, WARP как diagnostic fallback. |
| T3 | wave64 консоли на wave32 NVIDIA RTX 5060: различные результаты, расщепление на half-waves и снижение производительности | высокая | высокий | Эмуляция wave64 через две половины + обмен масками; явные тесты на lane ≥ 32; считать риск открытым. |
| T4 | Компиляция DXC на промахах кэша: секунды и гигабайты памяти, падение сессии (прецедент в XCL) | высокая | высокий | Ограничение HLSL размера/-O0; компиляция в отдельном процессе; Job Object memory cap; контент-адресуемый кэш. |
| T5 | UMA/память: 16 ГБ title memory vs 8 ГБ VRAM и 32 ГБ RAM | высокая | высокий | Бюджетирование, окна 4 ГБ, приоритет текстур, сброс неиспользуемых ресурсов, без полного зеркала памяти. |
| T6 | Драйвер NVIDIA может сбрасываться на некорректных консольных командах (VIctory сообщает о таком на реальном GPU) | средняя | высокий | DRED/GBV/отладочный слой; по умолчанию безопасный «отказ» операции; WARP для диагностики. |
| T7 | Огромная и недокументированная поверхность системных API | высокая | высокий | log-first: сначала трассировка вызовов, потом реализация; csv/таблица покрытия API. |
| T8 | Многопоточность: 6 ядер хоста против 7 игровых ядер консоли + потоки транслятора | высокая | средний | Приоритеты и affinity; вынос компиляции шейдеров в отдельные процессы; profiling с первого прототипа. |
| T9 | Форматы аудио (XMA, Opus, AWC), реверб, особенные режимы 3D-аудио консоли | средняя | средний | Начать с PCM/известных кодеков; трассировка форматов; честно помечать неподдерживаемые. |
| T10 | DirectStorage/BCPack/тайлинг текстур без эталонных данных | высокая | средний | Использовать только MIT-таблицы AMD/Mesa; синтетические control-тесты; не заявлять byte-exact без сравнения. |
| T11 | Хронология и билды: игра имеет версии 1.0.x, профили Series X/S различаются | средняя | средний | Профили конфигурации, определение build identity, версионирование кэша. |

## 4. Риски целевой конфигурации

| Ограничение | Последствие | Митигация |
|---|---|---|
| 8 ГБ VRAM | Невозможно держать все текстуры/BVH/RT консоли одновременно | агрессивный streaming, сжатие, приоритеты, 4 ГБ-окна UMA |
| 6 ядер / 12 потоков Ryzen 5 5600 | Конкуренция игровых потоков и потоков трансляции | фоновые задачи с низким приоритетом, пул потоков с лимитом, prefetch кэша |
| 32 ГБ RAM | Высокий commit при запуске games (по данным XCL ~15 ГБ в меню) | контроль Commit, настройка page file, мониторинг в диагностике |
| Windows 10: inbox D3D12Core (SM 6.5) | Нет SM 6.6 / mesh shaders | Agility SDK или Windows 11; проверка возможностей и понятное сообщение об ошибке |
| NVIDIA wave32 | wave64-шейдеры консоли работают медленнее/иначе | две половины + обмен; тесты; документировать расхождения |

## 5. Неизвестные факторы (их я не могу и не должен угадывать)

- Точное внутреннее устройство RAGE в GTA VI и его требования к API —
  публично неизвестны. Все соображения о RAGE в RESEARCH.md помечены как гипотезы.
- Точные структуры D3D12.X для графических команд (не compute) и формат
  записей draw — не реконструированы ни в одном публичном проекте полностью.
- Список системных вызовов, которые действительно использует GTA VI — неизвестен.
- Официальные PC-системные требования GTA VI на данный момент отсутствуют:
  Rockstar объявляет только PS5 и Xbox Series X|S.
- Легален ли статус конкретных публичных наборов данных, используемых
  сторонними проектами, — неизвестен; BrVIdge их не использует.

## 6. Процедура управления рисками

1. Каждый риск имеет владельца и триггер срабатывания (например, «тест
   падает на wave64 → повысить приоритет T3»).
2. После каждого этапа ROADMAP таблица пересматривается: риски закрываются
   только по результатам теста, а не по ощущению «похоже на рабочее».
3. Если риск L1 переходит в активную фазу (появление требований/претензий),
   разработка останавливается до юридического прояснения.
